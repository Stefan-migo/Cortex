# ODD Task — adopt-self-safety

## Objective

Make `cortex adopt` safe to run on a project that already exists: never destroy
project-owned files, never duplicate the injected `AGENTS.md` block, and never record a
baseline that launders the project's own content into a Cortex-owned file.

## Problem

`cortex adopt` is unsafe in three independent ways. All three were reproduced on a
disposable copy of this repository (`git archive HEAD` → `/tmp/opencode/adopt-repro`) using
the build of `ae459ef`.

### P1 — `--yes` overwrites project files with the template

`adoptProject` (`cli/src/engine/adopt.ts:112-116`) treats "target differs from the recorded
baseline" as a safe refresh. On a first run the baseline is empty (`oldHashes` = `new Map()`),
so **every** existing owned file is classified `refreshed`, and `--yes` or `--force` writes
the template content over it.

Literal evidence (`cortex adopt <copy> --yes`):

```
Refreshed (10):
  .opencode/agents/cortex-developer.md
  .opencode/agents/cortex-planner.md
  .opencode/mcp-template.json
  .opencode/skills/bootstrap/SKILL.md
  .opencode/skills/design-system/SKILL.md
  .opencode/skills/graphify/SKILL.md
  .opencode/tools/execute_script.ts
  .opencode/tools/package.json
  .opencode/tools/wiki-link.ts
  .opencode/tools/wiki-search.ts
```

The overwrite is destructive, not cosmetic:

```diff
--- pristine/.opencode/agents/cortex-planner.md
+++ adopted/.opencode/agents/cortex-planner.md
@@ -1,6 +1,5 @@
 ---
 description: "Cortex-Planner: ..."
-mode: primary
---
```

`--yes` is the standard non-interactive flag, and the only prompt
(`cli/src/commands/adopt.ts:26`) says `Adopt Cortex into "<dir>"?` — it never mentions the
overwrite. That is a footgun: the flag people use in scripts is the one that destroys.

### P2 — the injected `AGENTS.md` block is duplicated

`injectMarked` (`adopt.ts:43-48`) appends the block when the markers are absent. The markers
do not exist in `cli/template/AGENTS.md` (verified: `grep -n "cortex:start|cortex:end"
cli/template/AGENTS.md` → no match), so no project generated by `cortex init` carries them,
so the FIRST adopt of any Cortex project appends a second copy of sections that are already
there.

Literal evidence, on a copy of this repository (interactive run, no `--yes`):

```
headings before:  3     # ^## ODD Worktrees, ^## Reporting Cortex Defects, ^### 5-Step Execution Gate
headings after:   6
AGENTS.md diff:   31 added lines
```

The appended copy is the GENERIC template text and contradicts the project's own:
line 160 of the adopted file says the worktree path is `../<Project>-odd-<slug>`, while
Cortex's specific section says `../Cortex-odd-<slug>`. The project-specific section is the
correct one.

Note this happens **without** `--yes`: the duplication is the default behavior, not a
consequence of the dangerous flag.

### P3 — the manifest baseline records content Cortex never wrote

`adopt.ts:139` stores `hash: hashFile(join(targetDir, file))` — the hash of the file **on
disk**. For the files the run skipped (conflicts), that is the USER's content, so the
manifest claims Cortex owns it.

Literal evidence, manifest written by the interactive run:

```
file                                        manifest      project       template
.opencode/agents/cortex-developer.md        b379403594d9  b379403594d9  a518f4eafb1c
.opencode/agents/cortex-planner.md          8c75e3a39aaf  8c75e3a39aaf  3f5941ebcffe
.opencode/mcp-template.json                 c3cd440a81a3  c3cd440a81a3  b34e93f4ebb4
.opencode/skills/bootstrap/SKILL.md         64b5c26bafc1  64b5c26bafc1  bd0164427dd3
.opencode/tools/execute_script.ts           a22fc237a08e  a22fc237a08e  60cf1e0e3c5e
```

`manifest == project != template` means: baseline forged. Two consequences, both verified by
reading the consumers:

1. **The conflict is forgotten forever.** Re-adopting sees `oldHashes.get(file) ===
   hashFile(target)` and classifies the file as `skipped`, so a real divergence is never
   reported again. Measured: run 2 reports `Refreshed (0)`, `Skipped (19)`.
2. **`cortex update` silently overwrites the user's file.** `detectChanges`
   (`cli/src/engine/manifest.ts:90-97`) classifies a file as `modified` when
   `templateHash !== manifestHash && currentHash === manifestHash`. With the forged baseline
   both conditions hold immediately, and `update.ts:166-173` writes the template over the
   `modified` files **without any prompt** (only the `userModified` branch prompts,
   `update.ts:180-198`). So the corrupted baseline turns the user's content into an
   "auto-updatable Cortex file" and hands it to the one code path that never asks.

### P4 — `isDirty()` claims "clean" when it cannot tell

`adopt.ts:147-149` swallows every error and returns `false`. Running adopt against a
directory that is not a git repository printed a raw, contextless
`fatal: not a git repository ...` on stderr and then behaved as if the tree were clean:

```
fatal: not a git repository (or any parent up to mount point /)
Stopping at filesystem boundary (GIT_DISCOVERY_ACROSS_FILESYSTEM not set).

Cortex Adoption Plan (dry run)
```

### Accepted, not fixed: full re-serialization churn in JSON merges

`mergeJson` (`adopt.ts:87-88`) rewrites the whole file with `JSON.stringify(current, null, 2)`.
The change detector itself is sound (`changed` compares semantic JSON, so a no-op adopt writes
nothing), but when any key does change, the rewrite also reformats every unrelated literal:

```
opencode.json diff:           70 lines   (semantic delta: one added "plugin" key)
.opencode/opencode.json diff: 62 lines   (semantic delta: engram MCP + agent entries)
  -      "command": ["engram", "mcp"],
  +      "command": [
  +        "engram",
  +        "mcp"
  +      ],
  -      "_description": "Graphify \u2014 knowledge graph queries via MCP"
  +      "_description": "Graphify — knowledge graph queries via MCP"
```

Fixing this needs a format-preserving JSON editor, which is more machinery than the problem
justifies (Ponytail). It is recorded here as accepted, with the mitigation that a no-op adopt
writes nothing at all.

## Scope

**In scope** — `cli/src/engine/adopt.ts` and `cli/src/commands/adopt.ts`:

- P1: conflict classification + write gating, honest plan buckets.
- P2: section-aware, idempotent `AGENTS.md` injection.
- P3: manifest baseline invariant.
- P4: honest `isDirty` result.
- P5 (churn): documented as accepted.

**Out of scope**

- `cortex update`'s own defects (`update.ts` recognizes `OWNED_PATHS` never, never verifies the
  plugin path, `added` files prompt per file). P3's fix removes the forged-baseline path into
  it; update's remaining behavior is a separate change.
- Running `cortex adopt` on this repository for real. Not needed for this fix.
- Adding markers to `cli/template/AGENTS.md` (see D2).

## Design decisions

**D1 — `--yes` means "do not prompt", never "overwrite".** Overwriting project content
requires `--force`. The state machine per owned file becomes:

| target exists | target hash | baseline | classification | written |
| --- | --- | --- | --- | --- |
| no | — | — | `created` | yes (unless dry run) |
| yes | == template | — | `skipped` (already exactly ours) | no |
| yes | != template | == target | `refreshed` (ours, user never touched it) | yes (unless dry run) |
| yes | != template | != target or absent | `conflicting` (project's content) | only with `--force` |

`refreshed` now means what `cortex update` already means by `modified`: the file is exactly
what Cortex wrote and the template moved on. That case is safe by construction and no longer
needs a flag, which also removes today's double reporting (a refresh that is not applied is
currently listed in BOTH `Refreshed` and `Skipped`).

**D2 — fill gaps in `AGENTS.md`, never replace what is there.** Detection is by section
heading, not by markers, and injection is append-only:

- For each of the three sections (`## ODD Worktrees`, `## Reporting Cortex Defects`,
  `### 5-Step Execution Gate (MANDATORY)`), append it only when its heading is absent.
- If all three headings are present: no change at all (idempotent).
- No markers are added, and an existing marked region from an older adopt is left untouched.
  Replacing it would overwrite project-specific text — the exact risk P2 shows.

**D3 — a baseline records what Cortex owns, never what it found.** The manifest entry for an
owned file is the hash of the content Cortex would own, namely
`hashTemplateFile(source, templateOptions)` — the same function `detectChanges` compares
against, so the two agree by construction. For files Cortex actually wrote, this equals the
file's hash on disk; for conflicts it does not, which is the point: the divergence stays
visible to both `adopt` and `update`. If the existing manifest cannot be read or parsed, adopt
treats it as no baseline; D1 then classifies existing owned files as `conflicting` rather than
overwriting them.

**D4 — `isDirty` returns `boolean | undefined`.** `undefined` means "could not determine".
Git's stderr is piped, never inherited, so no raw `fatal:` line reaches the user.

## Acceptance criteria

1. Adopting a copy of this repository with `--yes` leaves all five divergent owned files
   **byte-identical** to their pre-adopt content (`sha256sum` comparison), and the run exits
   reporting them as `Conflicting`.
2. Adopting with `--force` overwrites exactly those files, and only with the flag.
3. Adopting a copy whose `AGENTS.md` already carries the three sections leaves its heading
   count at 3 and its content byte-identical.
4. A second adopt run over an already-adopted copy reports zero changes and leaves every file
   byte-identical.
5. After an adopt that left conflicts, the manifest hash for a conflicting file equals the
   template-derived hash, not the file's hash on disk, and `cortex update --dry-run` in that
   project does **not** list it as `modified`.
6. `cortex adopt --dry-run` against a non-git directory prints no raw `fatal:` from git and
   does not claim the tree is clean.
7. `npm run typecheck` and `npm run build` pass in `cli/`.
